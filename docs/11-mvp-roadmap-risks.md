### ما **لا** نبنيه في V1 (قرار واعٍ)
- تطبيق Flutter/React Native أصلي (PWA + TWA لاحقًا يكفي).
- OCR للوثائق الممسوحة (نعلّم `NEEDS_OCR` ونكتب يدويًا).
- تصحيح آلي لموضوع التحرير (essay) بالـ AI — حساس وغير موثوق؛ V1 = شبكة تقييم ذاتي.
- فيديوهات، بث مباشر، منتدى/مجتمع داخلي، دردشة.
- ترتيب وطني عام، "توقع النجاح"، أي ادعاء علمي بالجاهزية.
- اشتراكات بتجديد تلقائي/حفظ بطاقات.
- B2B (مراكز تكوين)، تعدد المؤسسات، التوسع المغاربي.
- OpenSearch / vector DB / microservices.

### ما يجب فعله قبل الإطلاق العام (ليس كودًا)
1. **التحقق البشري** من المناظرتين الأوليين (حقائق `needs_verification`) — مراجعة الصفحات الرسمية والرائد الرسمي.
2. **مراجعة 600–1,000 سؤال** للمناظرتين (≈ 10–15 ساعة بلوحة المراجعة) ثم `CONTENT_BETA_MODE=false`.
3. الإجراءات القانونية (INPDP، الشكل القانوني، الشروط) — `10-legal.md`.
4. مفاتيح Konnect/Flouci، VAPID، SMTP، النطاق، HTTPS.

## R. Kill Criteria (متى نتوقف أو نغير الاتجاه)

نقرر بعد **8 أسابيع** من بداية التحقق و**≥ 1,000 د.ت** إنفاق تسويقي:

| المؤشر | Kill / Pivot إذا |
|---|---|
| Waitlist + تسجيلات | < 300 خلال 4 أسابيع رغم 20+ منشور و500 د.ت إعلانات |
| إتمام التشخيص | < 30% ممن يبدؤونه |
| **Pre-sale** | < 15 دفعة حقيقية (أو < 1% من المسجلين) |
| CAC | > 3 × متوسط الإيراد لكل دافع (≈ > 120 د.ت) بعد تحسينين للإعلانات |
| Retention | D7 < 10% و D30 < 5% للمستخدمين المسجلين |
| الجودة | > 3% من الأسئلة المنشورة مُبلّغ عنها كخاطئة بعد المراجعة |

**مسارات الـ pivot قبل التوقف:**
1. الإبقاء على **التنبيهات + المعلومات الموثقة** كمنتج مجاني ممول بالإعلانات/الشراكات (الطلب على المعلومة مؤكد).
2. B2B: بيع المحتوى والمنصة لمراكز التكوين والجمعيات.
3. تغيير الشريحة: أساتذة/بنوك (رغبة دفع أعلى) بدل الأسلاك الأمنية.
4. التوسع إلى المغرب/الجزائر بنفس المنصة.
